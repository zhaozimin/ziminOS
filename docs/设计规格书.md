# ziminOS V1 工程设计规格书

> 版本 1.0 · 2026-08-09 · 本文件是 V1 实施的唯一事实源。实现与本规格冲突时，以本规格为准；本规格与原始脚本行为冲突且未标注「刻意偏离」时，以原始脚本为准。

## 0. 总则

- **产品**：Obsidian 插件 `ziminos`（显示名 ziminOS）+ 笔记库模板 `vault/` + 桌面智能体施工手册 `skill/SKILL.md`。
- **哲学红线（不可违背）**：
  1. 人主导：插件一切写入仅由用户命令或用户创建的文件触发，无定时器、无后台轮询。
  2. 脚本驱动：同输入同结果；插件内**零 AI 调用、零网络请求**。
  3. 只用 Obsidian 官方公开 API（`obsidian` 包导出），禁止访问未公开内部属性。
- **代码规约**：TypeScript；注释中文；单文件 ≤ 800 行；禁 `console.log`（用户可见反馈用 `Notice`）；禁魔法字符串（常量归 `core/constants.ts`）；每个业务文件必须带 GEB L3 头部注释（`[INPUT]/[OUTPUT]/[POS]/[PROTOCOL]`，PROTOCOL 固定为「变更时更新此头部，然后检查 CLAUDE.md」）。
- **原始脚本**（移植的事实源，逐行对照）：
  - `/private/tmp/claude-501/-Volumes-GuangTou-10------2026-2026-08-08-OBOS/02ed57ec-3bbf-4ca6-af9f-40932f6e45a6/scratchpad/original-scripts/create-project-moc.js`（335 行）
  - 同目录 `initialize-card-note.js`（296 行）
  - 同目录 `move-project.js`（681 行）
- **移植总规则**：行为与原脚本一致。仅允许三类替换：`quickAddApi.inputPrompt` → `core/modals.ts` 的 `TextInputModal`；QuickAdd 注入的 `settings` → 插件 `ZiminosSettings`；`QuickAdd.obsidian` 解构 → 直接 `import { ... } from 'obsidian'`。其余逻辑（含所有守卫、错误提示文案）原样保留。

## 5. 功能模块规约（并行实现阶段）

### 5.1 templates.ts（智能体 A）

导出纯函数（无副作用，全部返回 string）：

- `mocFrontmatter(description, created, uid): string`——与脚本一第 8 节 frontmatter 完全一致（aliases 空、description JSON 字符串化、created、updated 空、tags 空、UID 引号、type: project、status: active）。
- `mocBaseBlock(projectName, projectFolderPath): string`——与脚本一 `baseBlock` **逐字一致**（filters/properties/views/order/sort/columnSize 全部保留），仅项目名与路径参数化。
- `mocContent(...)`：frontmatter + 四个换行 + baseBlock + 换行（脚本一拼接规则：`${fm}\n\n\n\n${base}\n`）。
- `cardTemplateFile(): string` / `mocTemplateFile(): string`——手动插入用的模板文件内容，YAML 骨架、全字段空值：卡片十字段按 CARD_FIELDS 序；MOC 八字段（aliases/description/created/updated/tags/UID/type/status）。
- `navContent(): string`——`90-system/导航.md` 内容：一行说明文字 + base 代码块。base 块**只用等值筛选**（语法与脚本一 baseBlock 同族，禁用未经验证的函数式筛选）：四个 table 视图——「正在进行中」`status == "active"`；「项目」`type == "project"`；「领域」`type == "area"`；「书籍」`type == "book"`。列：file.name、note.description（displayName 概述）、note.status（displayName 状态）。
- `firstProjectDescription(): string`——「搭建属于我的个人知识管理系统」。

### 5.2 init.ts（智能体 A）

`export async function initializeVault(ctx: ZiminosContext): Promise<void>`，六步：

1. **空库检查**（仅当 `settings.initializedAt === ''`）：`vault.getMarkdownFiles()` 过滤掉根 `README.md` 与 `90-system/` 前缀后仍非空 → `Notice('检测到已有笔记，ziminOS 只在空库开荒。请新建一个空库再试。')` 并 return。已初始化过（initializedAt 非空）则跳过检查，进入幂等补齐。
2. **建文件夹**：遍历 INIT_FOLDERS，`ensureFolderPath`（天然幂等）。
3. **写模板**：TEMPLATE_FILES 两文件，`getAbstractFileByPath` 不存在才 `vault.create`（guard.mark 先行）。
4. **写导航**：NAV_FILE 同上规则。
5. **首个项目**（仅首次初始化）：TextInputModal 问「你的名字（用于创建第一个项目，Esc 跳过）」；输入非空 → 调 `createProject(ctx, { name: `${名字}OS_v1`, description: firstProjectDescription() })`；null/空 → 跳过，不视为失败。
6. **收尾**：`settings.initializedAt = nowStamp(...)`、`saveSettings()`、`Notice('开荒完成 ✅')`、`workspace.openLinkText` 打开导航文件。

全程 try/catch，失败 `Notice('初始化失败：' + message)`。

### 5.3 createProject.ts（智能体 B）

- `export async function createProject(ctx, preset?: { name: string; description: string }): Promise<TFile | null>`：无 preset 时两次 TextInputModal 问名称/概述（取消即中止，Notice 文案与脚本一相同）。其余与 create-project-moc.js 逐段对应：名称斜杠校验 → ensureFolderPath(项目根) → ensureFolderPath(项目文件夹) → 同名 MOC 拦截 → 生成内容（调 templates.ts）→ vault.create（guard.mark）→ getLeaf(false).openFile source 模式 → 光标定位 frontmatter 后（脚本一的 setCursor/scrollIntoView 逻辑原样）→ `Notice('项目已创建：' + name)`。项目根目录取 `ctx.settings.projectFolder`。
- `export function registerCreateProjectCommand(ctx): void`：命令 id `create-project`，name `新建项目`。

### 5.4 cardInit.ts（智能体 C）

- `export async function initCard(ctx, file: TFile, opts: { interactive: boolean }): Promise<void>`：initialize-card-note.js 主体移植。roots 由 settings.projectFolder/areaFolder 构造（Map 去重逻辑保留）；getCardContext、双缓存校验（缓存判一次、processFrontMatter 回调内再判一次）、description 仅首次询问、cardValues 十字段构造、reorderFrontmatter——全部原样。processFrontMatter 前 guard.mark。
- `export function registerCardInitCommand(ctx)`：id `init-card`，name `初始化当前卡片`，对 `workspace.getActiveFile()` 调 initCard（interactive: true）。
- `export function registerCardAutoInit(ctx)`：在 `workspace.onLayoutReady` 内 `plugin.registerEvent(vault.on('create', ...))`（官方推荐写法，避免启动期误触发）。守卫链，全部通过才触发 initCard：
  1. `settings.autoCardInit` 为 true；
  2. `file instanceof TFile && file.extension === 'md'`；
  3. `guard.isRecent(file.path)` 为 false（插件自建文件不触发，如 MOC）；
  4. 路径在 projectFolder/areaFolder 范围内（getCardContext 非 null 即为在范围，MOC 本体天然被排除）；
  5. **空文件校验**：`file.stat.size === 0`（同步工具带内容落盘的文件不触发——防止误改用户既有笔记）。

### 5.5 transitions.ts（智能体 D）

move-project.js（681 行）完整移植为四条命令：id `project-done/paused/dropped/active`，name `完成项目/暂停项目/放弃项目/重新开始项目`。TRANSITIONS 状态机、allowedStatuses 守卫、状态写入（processFrontMatter，guard.mark 先行）、整目录 `fileManager.renameFile` 搬移、冲突检测、搬移后重新打开、全部 Notice 文案——逐行对照原脚本，不增不减。activeFolder/archiveFolder 取 settings。文件若逼近 800 行，可拆出 `transitionEngine.ts`（同目录，智能体 D 自主决定，拆分后两文件都要 L3 头部）。

### 5.6 updatedMaintainer.ts（智能体 C）

`export function registerUpdatedMaintainer(ctx)`：`workspace.onLayoutReady` 内注册 `vault.on('modify')`。守卫链：`settings.autoUpdated` → TFile 且 md → 路径不在 `90-system/` 下 → `!guard.isRecent(path)` → 文件已有 frontmatter（`metadataCache.getFileCache(file)?.frontmatter` 存在；**不给无 YAML 的笔记强行注入**）。通过后进入 per-file 防抖（`Map<path, timeout>`，2000ms，注意 `plugin.register(() => 清理所有 timeout)`）；防抖到点后 guard.mark + processFrontMatter 设 `updated = nowStamp(settings.dateTimeFormat)`。processFrontMatter 自身引发的 modify 被 guard 抑制，无循环。

## 6. skill/SKILL.md（文档智能体 E）

Anthropic Skill 标准格式（YAML frontmatter：`name: ziminos-vault-setup`，`description` 一句话含触发场景「搭建/开荒 Obsidian 笔记库」）。正文步骤：

1. 问用户两件事：库放哪里（默认 `~/Documents/`）、库叫什么（默认 `ziminOS`）。

3. 收尾话术（原样输出给用户）：用 Obsidian「打开文件夹作为仓库」选中它 → 弹窗点「信任作者并启用插件」→ 设置 › ziminOS › 点「初始化」。
4. 红线：任何情况下不得删除/覆盖用户笔记文件；不得改动 vault 之外的任何路径。

仓库根 README.md（同智能体 E）：项目是什么（一句话 + 三角色图式文字版）、给学员的使用入口（把仓库地址交给桌面智能体说一句话）、给开发者的构建方式（npm install / npm run build）、目录导览、License。中文。
