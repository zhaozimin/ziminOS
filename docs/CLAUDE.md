## 成员清单

设计规格书.md: V1（v0.3.1，项目管理与灵感收集）的唯一设计事实源；描述已交付形态，是 V2 之前一切行为的判据。
设计规格书-V2.md: V2（v0.4.0 起）的唯一设计事实源，此后逐版追加章节；两文件并存，交集处以 V2 为准。它从人脉与复盘一路记到 v0.14.0 的读书系统：§16 作者名片、§17 检索边界与 README 落地、§18 正文字体、§19 纯文本导入、§20 一步读书、§21 ISBN 身份与豆瓣分类、§22 微信读书网关、§23 划线标注块与书目 YAML、§24 Apple Books WAL。§19 与 §20 必须合读：前者记录零网络约束下为何拒绝捆绑第三方同步插件，后者记录用户授权联网后为何把粘贴降为兜底；路线变了，解析与只增不删的合并内核没分叉。§22–24 则记录三类最危险的静默失败——HTTP 200 仍可能失败、旧笔记形态必须继续读得懂、SQLite 主库可能不是最新事实。
第三方组件.md: Dataview 查询组件、外观包、两套编译进 main.js 的图形（Pikaicons 命令图标、Simple Icons 品牌 logo）与四款正文字体（fonts/，v0.11.0 起）的供应链锁定表；记录上游版本、发布资产校验、许可证与用户配置保护边界，字体族还多记一项 name 表实测家族名——appearance.json 里写的名字以它为准，不以文件名为准。它还收着十二个 CSS 片段的清单：每个片段的来源、默认开关，以及落地时对原始文件做过什么处理——两处改动（文件图标前缀按 ziminOS 目录重写、水平滑轮的选择器收窄）在此备案，否则日后无从判断成品与上游为何不一致。Obsidian 平台本身的已知缺陷也备案于此（1.13.7 短代码块编辑态行装饰滞留，附根因与暂不硬修的理由）——平台就是最大的第三方，缺陷不记下来，日后只会被当成 ziminOS 的 bug 反复排查。
