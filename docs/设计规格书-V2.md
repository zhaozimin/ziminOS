## 0. 总则

### 0.1 V2 要长出来的东西

初始化后学员的库里直接站着两套系统：**人脉管理**（谁在变冷、谁欠谁人情、谁该送礼）与**复盘**（日→周→月→季→年一条主题链）。客户与付费是第三套，不进默认初始化，由一条独立命令按需长出。

### 0.2 四条已拍板的路线（不再讨论）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **视图由插件自渲染代码块**，不用 DataviewJS | 笔记里只留一行块名，逻辑全在 `main.js`；升级即全库生效，学员改不坏；DataviewJS 保持上游默认关闭，V1 规格 §3 不破 |
| 2 | **人脉+复盘进初始化，客户由命令按需长出** | 大多数学员不做生意，默认不给六张永远空着的销售表 |
| 3 | **新增 `05-diary`，根目录变七个** | PARA 四象限分的是「东西属于谁」，复盘分的是「什么时候发生」；两种坐标轴不塞进同一格 |
| 4 | **日主题建笔记时不问，由命令回填** | 主题是对一天的结论，早上答不出；实测强制弹自由文本 34/34 收到「123123」类垃圾，而垃圾能通过一切非空校验 |

### 0.3 三条红线在 V2 的具体含义

1. **人主导**：视图只在代码块被渲染时计算，重算由 `metadataCache` 变更事件触发，**不得引入任何 `setInterval` 轮询**（Dataview 的 2500ms 刷新正是我们不采用它的原因之一）。
2. **脚本驱动**：日记模板的**天气块整体删除**——它 `fetch` 三个 Open-Meteo 接口，插件内零网络请求不可破。地点/天气/温度三个字段一并从模板移除，不留空键（空键是登记表，不是索引）。
3. **只用官方公开 API**：视图引擎只允许用 `metadataCache.resolvedLinks`、`metadataCache.getFileCache().listItems/frontmatter`、`metadataCache.getFirstLinkpathDest`、`vault.cachedRead`、`MarkdownPostProcessor` / `MarkdownRenderChild`。**禁止** `getBacklinksForFile` 等未在 `obsidian.d.ts` 导出的内部方法。

### 0.4 V2 顺手关掉的两个缺口

- **`archived` 字段缺失（必修）**：`transitions.ts` 当前只写 `status`（`transitions.ts:287`），归档时刻无处可查。归档又走 `guard.mark`，`updatedMaintainer` 被自写抑制，连 `updated` 都不刷——「本月完成的项目」会把完成日记到学员最后一次手打该笔记的月份。修法见 §5.4。
- **`90-system/系统配置.md` 不再需要**：它存在的唯一理由是库内 dataviewjs 读不到插件设置。视图搬进插件后直接读 `ctx.settings.archiveFolder`，位置依赖彻底收敛到设置页，该文件不生成、不提及。

## 2. 视图引擎（V2 的核心新架构）

### 2.1 分层与归属判据

沿用 `core/CLAUDE.md` 的既有判据——**谈业务概念的归 modules，只谈文件事实的留 core**：

```
core/vaultIndex.ts   反向链接索引、列表行读取、字段读取        ← 不认识「人脉」
core/table.ts        表格 / 空态 / 提示的 DOM 渲染             ← 不认识「人脉」
core/codeblock.ts    ziminos 代码块解析、分发、生命周期与重算  ← 不认识「人脉」
core/markdown.ts     往指定小节里插一行（落地新增）            ← 不认识「人脉」
core/time.ts         日粒度口径与五级周期算术（扩充）          ← 不认识「人脉」
modules/*/…Views.ts  口径与语义（谁算超期、账本行怎么分段）    ← 业务全在这里
```

**落地差异一 · 新增 `core/markdown.ts`。** 三条命令都要往既有笔记的某个小节里追加一行（记人情写进日记、增加付费写进客户档案、记收款写进项目 MOC），规则完全一样。规则只该存在一份，而它不谈任何业务概念，所以归 core。

### 2.2 `core/vaultIndex.ts`

```ts
export interface ListLine {
    text: string;            // 去掉列表标记后的整行文本
    isTask: boolean;
    checked: boolean;
    links: string[];         // 行内 wikilink 的原始 linktext（未解析）
    line: number;
}
export class VaultIndex {
    backlinksOf(file: TFile): TFile[];
    resolve(linktext: string, sourcePath: string): TFile | null;
    listLinesOf(file: TFile): Promise<ListLine[]>;
    invalidate(): void;
}
export function dayOfFile(file: TFile): string | null;   // 文件名恰为 YYYY-MM-DD 才有值
```

四条必须写进实现的约束：

1. **反向索引一次构建，全渲染周期共享**。`resolvedLinks` 是 `Record<源, Record<目标, 次数>>`，逐个档案去正查是 O(人数 × 全库)。改为**一次遍历建 `Map<目标路径, TFile[]>`**，缓存到下一次 `metadataCache` 变更为止。这是 V2 唯一的常驻缓存，且由事件失效，不是轮询。
2. **行级链接必须经 `resolve()` 比对路径，禁止字符串匹配**。`listItems` 只给位置不给文本，链接更是原始 linktext；`[[张三|老张]]`、`[[人脉/张三]]`、`[[张三#约定]]` 三种写法指向同一文件。移植源 `person-ledger.js` 用正则拼文件名规避此事，V2 用 `getFirstLinkpathDest` 做得更正确——**这是允许优于原脚本的一处**。
3. **`listLinesOf` 靠 `cachedRead` 取文本，按 `listItems[].position` 切行，结果按 `file.stat.mtime` 缓存**。调用方永远只对「反链指向我的那几篇日记」调用它，不扫全库。
4. **`dayOfFile` 只认文件名，不认文件夹**。全库唯一的日记判据，与演示库口径一致（学员挪走 `05-diary` 也不坏）。

### 2.3 `core/codeblock.ts` 与块语法

学员在笔记里写的是：

````markdown
```ziminos
人脉名录
```

```ziminos
主题链
范围: 周
```
````

- **单一语言标记 `ziminos`**，第一非空行是视图名（中文，学员读得懂），其后每行一个 `键: 值` 参数，半角/全角冒号都接受。
- 未知视图名 → 渲染一行友好提示 + 当前可用视图清单，**不抛异常、不留白块**。
- 每个块包成 `MarkdownRenderChild` 并交给 `ctx.addChild()` 托管；`onload` 内订阅 `metadataCache.on('changed')`，带 200ms 防抖后重算；`onunload` 由基类自动解绑。
- 视图渲染函数签名：

```ts
export interface ViewContext {
    el: HTMLElement;
    sourcePath: string;                    // 宿主笔记路径：视图靠它知道「我长在谁身上」
    params: Record<string, string>;
    index: VaultIndex;
    ctx: ZiminosContext;
}
export type ViewRenderer = (view: ViewContext) => Promise<void>;
export interface ViewDefinition { readonly name: string; readonly render: ViewRenderer; }
export function registerViewCodeBlock(ctx: ZiminosContext, views: readonly ViewDefinition[]): void;
```

`main.ts` 只多一行装配：把三个模块导出的视图数组拼起来注册。**客户视图始终注册**（只读渲染，零成本），开关只决定初始化产物——避免任何需要重启才生效的条件分支。

### 2.5 渲染层纪律

- 表格一律经 `core/table.ts` 的 `renderTable(el, headers, rows)` 产出，单元格支持 `string | TFile | HTMLElement`；**禁止两次 `renderTable` 拼一张逻辑表**（两个 `<table>` 各自算列宽会错位，`review-daily-output.js` 的注释里已记录此教训）。
- 空态一律显式：`📭 + 一句话告诉学员下一步做什么`，禁止空块。缺记录的格子写「（无日记）」，**禁止兜底成 0**——16% 覆盖率下把空值伪装成零值，是最容易骗人的画面。
- 年度全景的柱状图沿用原脚本的纯 DOM + inline style 实现，不引入图表库，不新增 `styles.css`。

## 3. 人脉模块（`src/modules/contacts/`）

### 3.1 数据模型（逐条继承演示库，不发明新键）

人物档案 frontmatter，顺序即呈现顺序：

```yaml
aliases: · description: · created: · updated: · tags: · UID:
type: person
up: "[[人脉MOC]]"     # 归属链接，名录按它分组
tier:                 # 密/近/熟/远 = 7/30/90/365 天联系节奏
direction:            # 向上/平行/向下
gift:                 # true 即进投喂名单
address:              # 整串寄件信息，不参与筛选，唯一雇主是投喂名单
get:                  # 他能给我什么（List）
birthday:
```

三条不可动摇的口径：

1. **卡片不带分类**。没有「客户/生活/工作」枚举；圈子靠 `up`，客户身份靠「名下有 `client` 指向他的项目」从事实反推。身份因此不互斥。
2. **`client` 与 `with` 不能互换**。`client` 是商业契约标记，写下它等于把人注册成客户；朋友一起做的事走 `with`。
3. **位置无关**。全部视图靠 `type` 认身份，唯一位置依赖是 `settings.archiveFolder`（归档即退出名录）。

### 3.2 记录分工（三类记录同一入口，靠行的形态分流）

学员只在**当天日记**里写字，档案自己检索：

| 写法 | 落到哪 |
|---|---|
| `和 [[张三]] 去了新疆，谈定一起投网咖` | 档案「关键事件」 |
| `- [ ] 出网咖投资方案给 [[张三]]` | 档案「待办」 |
| `- [[张三]]｜去｜送了半斤生普｜两清` | 档案「人情账本」+ MOC「人情余额」 |

账本行纪律：全角 `｜` 分隔，`去/来` 必居第二段，状态取 `两清/我欠/他欠`（省略即两清），**人物归属只认首段的链接**——事项里被提到的人不算债主。非法状态值以 `⚠️` 前缀暴露，不静默吞掉。

### 3.3 文件清单

| 文件 | 职责 |
|---|---|
| `templates.ts` | 人脉/客户档案与两张 MOC 的文本生成，纯函数无副作用 |
| `createContact.ts` | 命令「新建人脉」：姓名 → 分层 → 方向三连问，`type: person` 由命令填、模板留空（模板自带 type 会让它自己变成名录里的一个人） |
| `recordFavor.ts` | 命令「记人情」：选人 → 去/来 → 事项 → 状态，账本行追加进当天日记；事项内全角 `｜` 清洗为半角防段错位；日记目录缺失自动创建，不以报错阻断 |
| `personViews.ts` | 档案四视图 |
| `circleViews.ts` | 人脉MOC 四视图 |
| `identity.ts` | 「谁还算数」的唯一答案处（落地新增）：身份靠 type、退出靠归档目录、最近联系只认日记 |
| `ledger.ts` | 日记三类记录的解析层（落地新增）：形态分流与「债主只认首段」的判据 |
| `client.ts` | 命令「初始化客户模块」「新建客户」「增加付费」「记收款」，以及 clientSeed |
| `clientViews.ts` | 客户八视图 |
| `seed.ts` | 人脉模块的开荒贡献 |

**落地差异二 · 拆出 `identity.ts` 与 `ledger.ts`。** 两处判据被命令侧与视图侧共同消费：「谁还算数」与「一行账本怎么归属到人」。留在任一视图文件里，另一侧就得抄一遍，而抄错的表现是视图静默少一行。

选人列表走 `metadataCache` 筛 `type: person`（客户命令筛 `type: client`），**归档目录内的人不进候选**。人机问答一律用 `core/modals.ts`，多选场景需要新增 `SuggesterModal`（基于官方 `FuzzySuggestModal`）——**枚举取代自由文本，让垃圾在语法上不可能产生**。

### 3.4 与 V1 既有自动行为的咬合（必须验证）

- `cardInit` 的放行闸是 `hasValue(frontmatter.type)`，`type: person` 的档案因此不会被补上 `rating/author/source/up` 四个无雇主的键——V1 已修对，V2 依赖它，回归测试必须覆盖。
- `02-areas/人脉/` 落在 `areaFolder` 内：插件建档走 `guard.mark` 不触发自动登记；**学员手工新建空笔记仍会被当卡片初始化**，这是既有行为，README 里说明「建档用命令」。

### 3.5 付费记录（客户模块）

任务行 + 中文行内字段，一笔一行不嵌套：

```markdown
- [x] [产品::Obsidian课] [金额::365] [日期::2025-08-19]
```

未勾＝待交付，勾上＝已交付，checkbox 直接充当交付状态。三条格式纪律各躲一个已核实的坑：键名用中文（含大写的键会被补一份规范名致求和双计数）、一笔一行（父子字段各自扁平上浮会丢配对）、产品名写在值里（当键名则算总收入必须枚举所有产品）。不设「付费次数/累计金额」字段——数行数即次数，求和即累计。

**V2 自渲染的红利**：这三条纪律里前两条是 Dataview 的解析行为所致；插件自己解析行内字段时不重蹈覆辙，但**格式仍按原样交付**，因为学员的库里可能同时装着 Dataview，两边看到的必须是同一笔账。

## 4. 复盘模块（`src/modules/review/`）

### 4.1 主题链

五级复盘的骨架不是数据，是一条主线：**日主题 → 周主题 → 月主题 → 季主题 → 年主题**。学员只在日记里写一次结论，其余四级全是它的投影。左边一句话是人写的，右边全部自动，两者并排才构成一次复盘。

### 4.2 周期笔记契约

| 级别 | `type` | 文件名 | 目录 | 周期锚点 |
|---|---|---|---|---|
| 日 | `diary` | `YYYY-MM-DD` | `05-diary/01-daily` | 文件名即日期，**无 `period_start`** |
| 周 | `weekly` | `GGGG-Www` | `05-diary/02-weekly` | `period_start` = ISO 周一 |
| 月 | `monthly` | `YYYY-MM` | `05-diary/03-monthly` | 月首日 |
| 季 | `quarterly` | `YYYY-Qq` | `05-diary/04-quarterly` | 季首日 |
| 年 | `yearly` | `YYYY` | `05-diary/05-yearly` | 年首日 |

**统一汇总键 `period_start`**（`YYYY-MM-DD` 定宽字符串）。所有区间比较一律降到 `YYYY-MM-DD` 字符串空间——定宽格式字典序即时间序，零日期算术、零跨年 bug、零跨类型比较陷阱。周归属月用 ISO 惯例：`period_start + 3 天`（周四）落在哪个月，该周就算哪个月，每周只归一个月，不重不漏。

导航行 `<< [[前]] | [[后]] >>　↑ [[上级|本周]]`：上级笔记不存在时是未解析链接，点击即按模板创建，这是 Obsidian 原生行为，不做额外处理。

## 9. 真机第一轮暴露的两处修正（v0.4.0 内修订）

### 9.1 选择弹窗永远返回「取消」

`ChoiceModal` 基于 `FuzzySuggestModal`。Obsidian 的 `SuggestModal` 在用户选中一项时是**先 `close()`、再回调 `onChooseItem`**，而 `onClose` 里同步把 Promise 结算成 `null`，于是每一次正常选择都先被判成取消，随后的 `onChooseItem` 因 `settle` 幂等而失效。表现：新建人脉 / 新建客户 / 记人情 / 增加付费四条命令永远只说「已取消」。

修法：`onClose` 先调 `super.onClose()`（基类自身的清理不能被覆盖掉），再把 null 结算推迟一拍。选中路径由 `onChooseItem` 先落定，取消路径没有后续回调、一拍后照常结算成 null。两条路径都成立，且不依赖基类的实现顺序。

### 9.2 UID 从 17 位字符串改为 14 位数字

属性面板要求 `UID` 是数字类型，而 JavaScript 安全整数上限是 `9007199254740991`（16 位）。17 位的 `YYYYMMDDHHmmssSSS` 一旦以数值形态落盘就会被静默四舍五入——真机第一轮已观测到 `UID: 20260812165253780` 这样末位归零的值，不报错、值已变，且此后每次读写都在错误值上继续。同一个库里还同时存在带引号的 `UID: "202608121704..."`（模板直接写字符串）与不带引号的形态，属性面板一半显示文本一半显示数字。

修法：`UID_FORMAT` 改为 14 位 `YYYYMMDDHHmmss`（2.03e13，稳在安全线内），`nowUid` / `nowStampAndUid` 返回 `number`，全部生成器落盘不加引号。代价是同一秒内建的两篇笔记会撞号——命令都是人触发的，一秒一篇是现实上限，这个代价远小于「主键会悄悄改数」。14 位也正是课程属性注册表 v4 原本写的位数。

### 9.3 属性类型不再需要学员手动设置

Obsidian 决定属性控件的依据是 `.obsidian/types.json`，它不看笔记内容——模板里的空字段因此一律显示成「文本」。

修法两件：其一，`vault/.obsidian/types.json` 随库交付，登记全部 25 个属性的类型（文本 12 / 日期时间 2 / 日期 3 / 数字 2 / 列表 3 / 勾选框 1 / 内置 2），全新安装即生效，升级只补缺失键不改用户调过的类型；其二，开荒生成 `90-system/属性类型示例.md`，每个属性都带一个格式正确的样例值，按类型分块说明。它住在 90-system 且 `type` 取封闭枚举之外的 `示例`，因此不会混进任何一个视图。

连带把 `up` 的落盘写法改成 YAML 列表（它登记为列表类型），`cardInit` 首次登记也写成单元素列表。

## 10. 真机第二轮暴露的修正（v0.4.0 内修订）

第二轮把插件自渲染的视图与原版 Dataview 并排比对，暴露的全是「像不像一个能用的系统」层面的问题——不是数据错，是呈现错。

### 10.1 建项目漏了归属这一步

移植源 `create-project-moc.js` 是四步：名称 → 归属（自己的 / 客户委托的）→ 选人 → 概述。V1 移植时只留了名称与概述两步，**归属分支整个丢了**——而 §3.1 明明写着「`client` 与 `with` 不能互换」，那条纪律因此没有任何入口去执行，全靠用户手写 frontmatter。

补法：命令恢复四步。顺序照原脚本——概述放最后，前面全是点选，中途取消不至于让人白写一段话；归属必须在动土之前问完，客户委托却没选到人时中止，不留半个空文件夹。选项文案直接把后果写出来（「自己的项目（不写 client，不进客户统计）」/「客户委托的（写 client，我欠他一个交付）」），因为这一问是整条流程里信息量最大的一步。

候选人住在 contacts 模块，projects 不 import 它——`createProject` 声明一个 `PersonPicker` 的洞，由 `main.ts` 用 `contacts/identity.ts` 的 `pickPerson` 填上。这是 §5.6 那套注入的第三处应用，方向与前两处相反（projects ← contacts）。

### 10.2 渲染层与 Dataview 的三处差距

| 差距 | 后果 | 修法 |
|---|---|---|
| 文本里的 `[[双链]]` 渲染成死文本 | 视图检索出来的是日记原文，原文里的人名与项目名都是双链——拍平成字符串等于把一张关系网变成一段文字，点不动、跳不了 | `core/table.ts` 新增 `RichText` 单元格与 `renderTextWithLinks`，链接按**来源笔记**的路径解析（事件行来自日记，不能按档案路径解析） |
| 任务行渲染成表格 | 待办不像待办，也勾不掉 | 新增 `renderTaskList`：一条一行、真复选框、日期缀在句尾且可点、勾选写回源文件那一行；写前比对原文，行号漂了就什么都不做 |
| 全框线表格 | 与 Dataview 的三线表风格分裂，同一个库里两种表 | 新增 `vault/.obsidian/plugins/ziminos/styles.css`：三线表、首列表头带行数计数、选择器全带 `ziminos-` 前缀、颜色取 Obsidian 语义变量 |

`styles.css` 是插件的第三个交付文件（前两个是 `main.js` 与 `manifest.json`），手工维护、不经 esbuild，已加入 SKILL 的交付清单与升级复制清单。

**只认双链一种标记，不接完整 Markdown 渲染器**：这些文本是用户日记里的原话，交给渲染器等于把用户数据当代码执行，一个 `![[大图]]` 就会在名录里嵌进一张图。

### 10.3 相关项目的口径修正

原实现列「项目 / 关系 / 状态」，且不分状态全列。改为：

- 列 **项目 / 关系 / 概述**——状态这一列在只剩进行中的表里恒定重复，概述才是决定要不要点进去的信息。
- **只列未终结的项目**。走到 `done` 或 `dropped` 的项目从「相关项目」移进「关键事件」，带着 `archived` 给的确定日期。理由是这四个视图本就是一条时间线：相关项目答「我们现在手上有什么」，关键事件答「我们之间发生过什么」。一个三年前做完的项目永远挂在「相关项目」里，是把履历当成待办。


### 10.4 版面：表格占满整行，待办收成一行

真机第三轮的反馈是「自适应到了最小宽度」——表格缩成内容宽度挤在左边，右侧大片空白没人用；待办则被日期分组标题拉长了一倍。两件都是空间分配问题。

**表格**：`.ziminos-table` 这一级压不住 Minimal 给 table 设的收缩宽度，选择器改成 `div.ziminos-table-wrap > table.ziminos-table` 两级。光撑满还不够——余量得有人收：`renderTable` 新增可选的 `grow` 参数指出哪一列是句子列，其余列 `width:1px + nowrap` 各取所需，句子列拿走全部余量。只在真有句子列的表上指定（概述、事项、发生了什么、一句话、寄件信息、各级主题、笔记），其余交给浏览器均摊。

**待办**：去掉按日期分组，改走与其余视图同一个 `renderTable`，画成三线表（事项一列、日期一列，事项列吃余量）。复选框与事项同处一格——分成两列的话一个待办会被表格的列切成两半，而勾选框离它要勾的那句话越远越容易勾错。格内用 flex 两段，事项段显式 `min-width: 0`：flex 子项默认 `min-width: auto`，长句子会撑破单元格。

**全宽**：两级选择器仍不足以撑满——主题可能用 `!important` 锁死表宽，那场特异性竞争赢不了。改用 `min-width: 100%`：它不参与竞争，浏览器先算出 `width` 的用值再拿 `min-width` 去夹，于是无论主题把 `width` 设成 `fit-content` 还是别的什么，最终宽度都不会小于整行。这比自己也写一个 `!important` 干净——我们并没有覆盖主题的意图，只是声明一条下限。
