# src/modules/review/

> L2 | 父级: ../../CLAUDE.md

复盘模块。它替代的是课程原方案里 Templater + 日历插件 + 五份分发型模板那一套：五级笔记的文件名、目录、导航链接与周期锚点全部由日期算术确定性地推出，同输入同结果，无网络、无模板引擎。

它的骨架不是数据，是一条主线——**日主题 → 周主题 → 月主题 → 季主题 → 年主题**。学员只在日记里写一次结论，其余四级全是它的投影。左边一句话是人写的，右边全部自动，两者并排才构成一次复盘。

## 成员清单

templates.ts: 五级笔记的正文生成器，纯函数。相对课程原模板只做两处刻意删改，都不是省事：天气块整体删除（它要 fetch 三个外部接口，而插件内零网络请求是红线，location/weather/temperature 三个字段一并移除，不留空键当摆设）；theme 建笔记时留空（结论早上答不出，且实测强制弹自由文本会得到 34/34 篇「123123」类垃圾，而垃圾能通过一切非空校验并作为事实进入汇总表）。另导出 viewBlock，全仓库每一处视图代码块都从它出，学员笔记里的写法因此永远与引擎认的写法一致。
periodic.ts: 模块的入口与坐标系。五条打开命令、目录解析、周期归属判定、区间解算都在这里。命令身份住在 core/commands 的 PERIOD_COMMANDS，键与 PERIODS 同源且类型是 Record<PeriodKey, …>——「加一级周期却忘了给它命令」因此在编译期就过不去；PERIODS 那张表则只谈时间，格式串、startOf 单位与上下级关系。「不存在就建，存在但是空文件就补齐骨架，有内容就一个字不动」是它的幂等姿态。它刻意不写 daily-notes.json——核心日记插件会建出不带模板的空文件，播种那份配置等于给学员造一条通向空白笔记的岔路。周期锚点一律取左闭右开区间，五级共用同一条比较式，不存在「月末那天算不算」这类边界分歧。
theme.ts: 主题链的唯一录入口，一条命令覆盖五级——站在周记上写周主题，站在别处写今天的日主题（顺带把今天的日记建出来）。弹窗带出现有值可直接改写，但留空不清空：误触 Esc 或空回车不该把已经写好的结论抹掉。
views.ts: 主题链的自动侧两视图（今日产出、主题链）。它们共守一条纪律——缺记录必须显式留空。实测日记覆盖密度只有 16%，把空结果兜底成 0，等于把「本月没记录」伪装成「本月跑了 0 公里」，所以每张表都把「几分之几有记录」和结论摆在同一屏。
projectViews.ts: 项目数据横向汇入的三视图（项目动态、完成的项目、年度全景）。三者的分工本身就是方法论：周看哪些项目在动（周期短，动作即信号），月与季看完成了哪些（周期长，新建只说明起了念头，完成才说明真推进了），年看格局（四态分布与月度节奏，事件折叠成计数与柱子）。往年的年记必须换个说法——status 只有当前值，无法回溯到那一年的年末，假装它是那一年的快照就是拿今天的事实冒充历史。
seed.ts: 开荒贡献，只申报目录不申报笔记。开荒时预建一篇空日记，会在时间轴上留下一个「那天什么都没发生却有记录」的假点。

## 模块契约

对外只暴露 reviewSeed、registerPeriodicCommands、registerThemeCommand、openPeriodNote 与两个视图数组，由 main.ts 调用。openPeriodNote 带一个 reveal 开关：记人情那类「顺手记一笔」的动作只需要日记存在，不该顶掉学员正在读的笔记。

**周归属月一律按 ISO 惯例以周四为准。** 每周只归一个月，不重不漏。按周一归属的话，跨月那一周会在两个月里各出现一次，或者一次都不出现——两种错法都不会报错。

**日记刻意没有 period_start。** 它的文件名就是日期，多写一个字段等于给同一件事两个事实源，而两个事实源迟早会分叉。

「本周期完成了哪些项目」以 MOC 的 archived 为准，那是状态流转命令与 status 同一次写入落的确定事实；回落 updated 只为兼容 V2 之前建的项目。这条依赖必须记住：projects 模块若不写 archived，本模块的月记与季记会静默算错——不报错，只是把完成日记到学员最后一次手打那篇笔记的月份。
