# src/modules/about/

> L2 | 父级: ../../CLAUDE.md

关于作者模块。它不生产笔记、不报 VaultSeed、不注册命令；它只把作者的入口（官网与教程的 .cn/.com 双部署、GitHub 开源仓库、X / YouTube / B站 / 小红书四个自媒体频道）编译进 main.js。存在的理由是传播经济学：插件会脱离仓库单独流传，而 main.js 是唯一一定跟着走的文件——名片长在它身上，插件传到哪，作者就被认识到哪。

## 成员清单

view.ts: 数据与渲染。链接、五段 Simple Icons 品牌图形（CC0，见 docs/第三方组件.md）与星图 logo（逐字取自 edu 站 favicon.svg：墨底、纸色折线、一颗朱砂点）是本文件的数据源，改链接只改这里；renderAboutPanel 把名片画进任意容器，不接收 ctx 不读设置——内容是编译期常量，在任何库里画出来都一样。版式（v0.9.4 定稿）：最上两枚站点磁贴（头像＝官网、星图＝插件教程），站是国内外一体的，一枚磁贴装 .cn/.com 两个域名、各自成行可点；磁贴之下频道胶囊按地域切上「海外」下「中国大陆」两区——平台才分边，站不分边，分组本身就是「哪边快用哪边」的解释。胶囊 = 品牌原色图标 + 作者的平台账号名。品牌色的取舍：GitHub 与 X 的官方标就是黑白两版，取 currentColor 随主题走正是「原本的颜色」；YouTube/B站/小红书按官方色值写在元素上而不进 styles.css，因为品牌色是数据的一部分，与主题无关也不该被主题改。
avatar.ts: 素材层，作者头像照片的 data URI（JPEG 160px，约 19KB）。编译进 main.js 而非随库放图片文件——名片的立身之本是「插件传到哪它跟到哪」，而 main.js 是唯一一定跟着走的文件；data URI 渲染零网络请求，红线不破。独立成文件是因为它是一整行近两万字符的机器数据，混进 view.ts 会把人读的数据表淹掉。

## 两个挂载位

同一个 renderAboutPanel 挂两处，覆盖两条传播路径：其一，「关于作者」视图（名字住在 core/constants 的 ABOUT_VIEW——它是唯一被两个模块引用的视图名，projects 模块的导航页模板照着它写块），开荒后学员每天打开的首页底部就是它；其二，设置页开荒页尾的落款（经 SettingActions 的 renderAbout 洞由 main 填上，设置页不 import 本模块），排在高级折叠之后——它不是设置，是署名。没开过荒、只拿到 main.js 的库打开设置第一眼就是开荒页，拉到底就看得见。v0.9.0 它曾是第十张标签页，v0.9.2 收回页尾：一张名片撑一整页是把分页做成摆设。

删掉本模块，二十二个视图少一个、导航页底部那个块降级为「没有名为×的视图」的空态提示、设置页开荒页尾少一段落款，其余功能零损失。
