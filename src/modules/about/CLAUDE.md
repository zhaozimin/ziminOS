# src/modules/about/

> L2 | 父级: ../../CLAUDE.md

关于作者模块。它不生产笔记、不报 VaultSeed、不注册命令；它只把作者的入口（官网与教程的 .cn/.com 双部署、GitHub 开源仓库、X / YouTube / B站 / 小红书四个自媒体频道）编译进 main.js。存在的理由是传播经济学：插件会脱离仓库单独流传，而 main.js 是唯一一定跟着走的文件——名片长在它身上，插件传到哪，作者就被认识到哪。

## 成员清单

v0.15.0 的思路致谢增加 Dust Calendar，许可署名增加编译进 main.js 的 lunar-typescript 与内置节假日快照所沿用的 holiday-cn。这些署名必须与 docs/第三方组件.md 及 main.js banner 同步；否则名片会对用户声称一份不存在的许可边界。

view.ts: 数据与渲染。链接、五段 Simple Icons 品牌图形（CC0，见 docs/第三方组件.md）与星图 logo（逐字取自 edu 站 favicon.svg：墨底、纸色折线、一颗朱砂点）是本文件的数据源，改链接只改这里；renderAboutPanel 把名片画进任意容器，不接收 ctx 不读设置——内容是编译期常量，在任何库里画出来都一样。版式（v0.9.4 定稿）：最上两枚站点磁贴（头像＝官网、星图＝插件教程），站是国内外一体的，一枚磁贴装 .cn/.com 两个域名、各自成行可点；磁贴之下频道胶囊按地域切上「海外」下「中国大陆」两区——平台才分边，站不分边，分组本身就是「哪边快用哪边」的解释。胶囊 = 品牌原色图标 + 作者的平台账号名。品牌色的取舍：GitHub 与 X 的官方标就是黑白两版，取 currentColor 随主题走正是「原本的颜色」；YouTube/B站/小红书按官方色值写在元素上而不进 styles.css，因为品牌色是数据的一部分，与主题无关也不该被主题改。v0.14.0 起名片以「致谢」收尾，位置就是态度——一张自我介绍的卡片，最后一段留给别人；整块压到弱化色与小一号字，这一段该被读到，不该被点着走。它分两块，两块的性质不同：上面 `CREDITS` 是**思路**（一行代码没抄，但少了谁就会走错），判据只有一条「没有它，这里会走错」，因此每条后面那句话必须指得出具体的东西——是它让我们知道豆瓣的 JSON 接口走不通、是它让我们知道苹果图书的划线躺在哪个 SQLite 里；「优秀的开源项目」这种句子一条都不要，那是客套不是致谢，读者看完应该确切地知道欠了谁什么。排序即欠得多少，不是字母序。下面 `BUNDLED` 是**随库或随 main.js 交付的第三方资产**，那是许可要求的署名不是客套，所以只列名字与许可证、连排成一段文字而不是又一列条目——排成清单会让它看起来和上面一样重要，而它只是一行字（明细在 docs/第三方组件.md，两处须同步）。
avatar.ts: 素材层，作者头像照片的 data URI（JPEG 160px，约 19KB）。编译进 main.js 而非随库放图片文件——名片的立身之本是「插件传到哪它跟到哪」，而 main.js 是唯一一定跟着走的文件；data URI 渲染零网络请求，红线不破。独立成文件是因为它是一整行近两万字符的机器数据，混进 view.ts 会把人读的数据表淹掉。

## 两个挂载位

同一个 renderAboutPanel 挂两处，覆盖两条传播路径：其一，「关于作者」视图（名字是本模块的局部常量，库内唯一消费方是 vault/README.md 里手写的代码块，改名须同步 README）——v0.10.0 起名片住在 README 而不再写进导航（导航是工位，署名在介绍文档里才是署名），v0.10.1 起顶在 README 最前，且开荒完成后第一个打开的就是 README——安装初始化那一下（设置开荒页尾）与开荒完成第一屏（README 顶部）各见一次，全插件的广告位仅此两处；其二，设置页开荒页尾的落款（经 SettingActions 的 renderAbout 洞由 main 填上，设置页不 import 本模块），排在高级折叠之后——它不是设置，是署名。没开过荒、只拿到 main.js 的库打开设置第一眼就是开荒页，拉到底就看得见。v0.9.0 它曾是第十张标签页，v0.9.2 收回页尾：一张名片撑一整页是把分页做成摆设。

删掉本模块，二十二个视图少一个、README 里那个块降级为「没有名为×的视图」的空态提示、设置页开荒页尾少一段落款，其余功能零损失。
