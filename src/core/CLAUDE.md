# src/core/

> L2 | 父级: ../CLAUDE.md

基础设施层。判断一个文件该不该住在这里只有一条标准：它是否谈论「项目」「卡片」「归档」「人脉」这类业务概念——谈了就属于 modules，不谈才留在 core。V2 兑现了这句话：人脉与复盘两个模块加进来时，core 只是长出了三个同样不懂业务的新文件（事实层、呈现层、宿主），原有七个文件的语义一个字没改。外观包属于 vault 交付物，不依赖插件 core。

## 成员清单

constants.ts: 全仓库唯一常量源，零 import，是依赖图最底层的叶子。七个根目录、系统笔记路径、卡片十字段序、统一字段名 FIELDS 与身份枚举 NOTE_TYPES、时间与日粒度格式、灵感默认值、自写窗口、项目状态机 TRANSITIONS、五级复盘周期表 PERIODS、人脉三轴与人情账本格式、付费流水字段、外观开关的片段目录名与 appearance.json 键名、视图代码块契约，全在此。片段扩展名之所以是常量而非就地写死，是因为它同时是筛选判据与截断长度，两处必须同源。FIELDS 单独收口的理由是：视图靠字段认事实、命令靠字段写事实，两边写错一个字母就静默失联——而 YAML 里查不到的空字段既不报错也留不下痕迹。
types.ts: 契约层。ZiminosSettings 与 DEFAULT_SETTINGS 定义可持久化设置，ZiminosContext 定义模块获取能力的唯一形态，VaultSeed 定义一个模块对开荒的全部诉求。新字段以默认值打底，老库升级不需要迁移脚本。
time.ts: 时间口径统一处，也是 dateTimeFormat 的守门人。原始脚本的手写时间统一收敛为 moment；nowStampAndUid 保证 created/UID 同源，nowLocalDateTimeParts 保证灵感模板的 date/time/datetime 在同一时刻生成。调用方不自行 new Date 拼时间，避免跨秒或跨分钟分叉。
folders.ts: 目录保障。ensureFolderPath 逐级创建并在同名文件挡路时抛出明确错误；normalizeFolderPath 把用户在设置页敲进去的自由文本收敛成可用路径，空值回落默认——校验集中在读取侧，是设置页敢于不做校验的前提。
frontmatter.ts: YAML 字段判定与重排。hasValue / isCardInitialized / reorderFrontmatter 决定「一篇笔记算不算已登记的卡片」；isMocFrontmatter 是规格授权的一处刻意偏离，把 MOC 判据从 type ∈ {project, area} 放宽为 type 有值，否则 type: book 的 MOC 会被误当卡片改写。
modals.ts: 唯一人机问答通道。把弹窗生命周期翻译成 Promise：有输入返回文本，取消返回 null，调用方因此能用一条 if 中止流程。两个弹窗的分工是纪律而非口味——凡取值来自封闭集合（分层、方向、去/来、状态、产品、渠道、选人）一律走 ChoiceModal。实测证据是硬的：用自由文本问「今天做了什么」，34 篇日记收到 34 个「123123」类垃圾，而垃圾能通过一切非空校验并作为事实进入汇总表。枚举让垃圾在语法上不可能产生，这比任何校验都可靠。
vaultIndex.ts: 视图引擎的事实层，二十一个视图的唯一数据来源。它只回答关于文件的客观问题——谁链到了我、这个链接指向哪个文件、这篇笔记有哪些列表行。它取代的是 Dataview 的索引层，因此必须补上后者两个已知的坑：其一，行级链接在 Dataview 里未被规范化成完整路径，逐字比对恒为 false 且静默返回空，这里一律经 getFirstLinkpathDest 解析成文件再比对，别名、子路径、锚点三种写法都认得；其二，Dataview 靠 2500ms 轮询刷新，而红线不许轮询，这里改为懒构建 + 修订号自校验，两次渲染之间没有任何后台活动。反向链接表一次遍历建成、同一渲染周期共用，把「人数 × 全库」降成「全库」。
table.ts: 视图引擎的呈现层，只认识「表头 + 行 + 单元格」与「一组任务」。三条纪律都来自与原版 Dataview 的真机对比：其一，文本里的 `[[双链]]` 必须渲染成可点的链接——视图检索出来的是日记原文，原文里的人名与项目名都是双链，渲染成死文本等于把一张关系网拍平成一段字符串；其二，任务行渲染成真的复选框并能勾，勾选写回源文件那一行，因为看起来像复选框却点不动是撒谎；日期缀在句尾而不另起分组标题——档案里的待办通常一天只有一两条，分组的收益是零、代价是整整一倍的纵向空间。其三，表格是三线表并占满整行，且由调用方指出哪一列是句子列去吃掉余量：不指定的话浏览器按内容比例摊给每一列，结果是每列都窄一点、每列都要换行；逻辑上同一张表还必须一次画完（两次建表会得到两个各自算列宽的 table，列必然错位）。它只认双链一种标记而不接完整 Markdown 渲染器：那些文本是用户日记里的原话，交给渲染器等于把用户数据当代码执行。空态有专门的原语且强制带一句下一步指引。样式在插件自带的 styles.css 里，全部选择器带 ziminos- 前缀、颜色取 Obsidian 语义变量，因此跟随主题与配色走；表格那几条刻意写成两级选择器，否则 Minimal 一类主题给 table 设的收缩宽度会把表挤成内容宽度。
codeblock.ts: 视图引擎的宿主，把「学员写下的一个代码块」翻译成「一次视图渲染」，并管住这次渲染的全部生命周期。它不认识任何具体视图，清单由 main 装配时递进来。重算策略是它最关键的设计：变更事件只递增修订号并排一次防抖，到点后由宿主统一重算全部在场的块——既不轮询，也不会出现「块比索引先醒来、拿着上一版数据重画一遍」的竞态，因为失效与重算由同一个入口先后执行，顺序不依赖事件注册的先后。
markdown.ts: 纯文本操作层，两件事。其一，往既有笔记的某个小节里追加一行记录（记人情写进日记、增加付费写进客户档案、记收款写进项目 MOC）——三个落点规则完全一样，所以规则只存在一份。其二，翻转某一行的复选框：写之前先比对那一行还是不是预期的那条任务，对不上就返回 null 让调用方什么都不做——视图渲染之后用户可能改过源文件，行号会漂，而勾错一条别人的待办比没勾上难发现得多。三条行为都是为了让插进去的那一行看起来像人自己写的：插在视图代码块之前（数据在上、汇总在下）、用掉模板留下的空占位行、找不到小节时宁可追加到文末也绝不拒绝写入——学员改过标题不该导致他的记录丢失。
guard.ts: 自激循环断路器。插件的自动化监听 vault 事件，而插件自己的写盘同样触发这些事件——所有写路径动手前 mark，所有监听动手前问 isRecent，两端配合把「机器的动作」与「人的动作」区分开。isRecent 遍历时顺手清过期项，不另起定时器，守住「无后台轮询」红线。

## 内部依赖

constants 零依赖，是依赖图最底层的叶子。绝大多数文件只依赖 constants 与 obsidian；横向依赖只有两条，都指向更底层：types 引用 guard 的类型，codeblock 引用 vaultIndex、table 与 types。方向始终由「懂得多的」指向「懂得少的」，故 core 内部无环。
